# PY32F002B 显示与按键系统说明

## 1. 文档目的

本文档以当前工程代码为准，说明系统的启动流程、主循环、按键功能、LED 矩阵扫描、数码管显示、模式和单位选择、电池图标、DC 指示灯以及 Option Byte 复用配置。

串口 AA55 通信规则、`CMD=0x01` LED 开关、`CMD=0x02` 状态查询和 `CMD=0x03/0x04` 压力泵控制请参阅工程根目录的 [控制协议设计说明.md](控制协议设计说明.md)。

应用层代码位于 `Src/` 和 `Inc/`，芯片官方 HAL、LL、CMSIS 和启动文件位于 `Drivers/`，两者职责不同。当前应用层已经统一使用 HAL API，不再调用 LL API；`Drivers/` 中保留的 LL 文件只是官方库内容。后续增加业务功能时，优先调用本文档列出的应用接口，不要在业务代码中直接操作矩阵 GPIO。

## 3. 上电和主循环

### 3.1 启动顺序

`main()` 的执行顺序如下：

1. 调用 `HAL_Init()` 初始化 HAL 和 1 ms SysTick 时间基准。
2. 使用 `HAL_RCC_OscConfig()`、`HAL_RCC_ClockConfig()` 启用 24 MHz HSI，并将 SYSCLK、AHB、APB1 配置为 24 MHz。
3. `HAL_Delay(5000U)`，上电稳定等待 5 秒。
4. 调用 `option_bytes_boot_check()` 检查当前 SWD/PC0/PB6 复用状态。
5. 初始化按键驱动 `key_init()`。
6. 初始化 LED GPIO、显示缓存和扫描状态 `led_init()`。
7. 初始化模式、单位、压力、电池和 DC 等应用状态 `display_control_init()`。
8. 通过 `uart_control_init()` 统一初始化 PB4 单线半双工串口、AA55 协议解析器和通信事务锁。
9. 进入永久主循环。

当前工程的上电延时是 5 秒，不是 10 秒；如需调整，只需修改 `Src/main.c` 中的 `HAL_Delay(5000U)`。

### 3.2 主循环

```c
while (1)
{
    key_scan();
    led_scan();
    display_control_scan();
    uart_control_task();
    uart_command_scan();
}
```

- `key_scan()`：每 10 ms 实际采样一次按键，其他循环次数只返回。
- `led_scan()`：每 1 ms 切换一个扫描时隙，完成 LED 矩阵动态显示。
- `display_control_scan()`：消费按键事件、处理 S1 短按压力泵启动/暂停、切换模式/单位、调整目标压力、切换 S3 短按对应的 LED 状态、消费充电状态和压力泵状态查询结果、推进电池动画并检查 S1/S3 长按。
- `uart_control_task()`：非阻塞处理 USART1 中断解析出的完整 AA55 返回帧，并检查 100 ms 超时。
- `uart_command_scan()`：每 1000 ms 提交一次 `CMD=0x02` 充电状态、电量、Pa 气压和压力泵状态查询；串口忙时顺延。

显示缓存由应用驱动更新，GPIO 输出由 `led_scan()` 统一完成。应用模块不直接和其他模块争抢高边、低边 GPIO。

## 4. 硬件和引脚映射

### 4.1 高边公共端

高边由 SS8550 等 PNP 管驱动，输出低电平选通，输出高电平关闭。

| 公共端 | GPIO | 扫描索引 |
| --- | --- | --- |
| Q1 | PB6 / P01 | 0 |
| Q2 | PA1 / P06 | 1 |
| Q3 | PA2 / P07 | 2 |
| Q4 | PA4 / P08 | 3 |
| Q5 | PA3 / P09 | 4 |
| Q6 | PB0 / P10 | 5 |
| Q7 | PA7 / P11 | 6 |
| Q8 | PC0 / P15 | 7 |

### 4.2 低边和按键复用

低边输出低电平吸电流，LED 点亮；输出高电平，LED 熄灭。前 6 条低边和按键共用，按键扫描时会临时改为上拉输入，采样结束后恢复推挽输出。

| 低边索引 | LED/网络 | GPIO | 复用按键 |
| --- | --- | --- | --- |
| 0 | L00 / P00 | PA0 | S1 |
| 1 | L02 / P02 | PB1 | S5 |
| 2 | L03 / P03 | PB3 | S6 |
| 3 | L04 / P04 | PB2 | S4 |
| 4 | L05 / P05 | PB7 | S3 |
| 5 | L12 / P12 | PC1 | S2 |
| 6 | L13 / P13 | PA6 | 无 |
| 7 | L14 / P14 | PA5 | 无 |

当前 UART 已使用独立的 PB4 单线半双工复用，不占用 S4/L04 对应的 P04/PB2 低边线。硬件配置头文件中的历史 `RX_TX_GPIO_*` 宏仅作为旧映射记录，协议通信以 `uart_halfduplex_driver.c` 的 PB4 配置为准。

## 5. LED 矩阵扫描

### 5.1 扫描结构

LED 驱动使用 8 行矩阵加 2 个辅助时隙：

| 时隙 | 内容 |
| --- | --- |
| 0~7 | Q1~Q8 普通矩阵行，输出 `s_frame[0]`~`s_frame[7]` |
| 8 | Q1/L01 辅助时隙，驱动模式灯和 DC 指示灯 |
| 9 | 单位灯辅助时隙，前三个单位使用 Q1，最后一个使用 Q4 |

每个时隙持续约 1 ms，完整周期约 10 ms，理论刷新频率约 100 Hz。切换时先关闭所有高边，再更新低边，最后打开目标高边，以减少串光和鬼影。

### 5.2 一个扫描时隙的执行过程

以普通矩阵行 `Q3` 为例，`led_scan()` 每到一个 1 ms 时隙会按以下顺序执行：

```text
关闭 Q1~Q8 全部高边
        |
        v
根据 s_frame[2] 设置 8 条低边 L00~L14
        |
        v
拉低 Q3 高边，选通 Q3 这一行
        |
        v
保留约 1 ms，下一次调用时切换到下一行
```

高边由 PNP 管控制，低电平表示选通；低边由 GPIO 吸电流，低电平表示点亮。因此一个 LED 只有在“对应高边已选通”和“对应低边 bit 为 1”两个条件同时满足时才会亮。切换行时先关闭高边，可以避免上一行和下一行同时导通造成串光。

8 个普通行扫描完成后，驱动还会执行两个辅助时隙：

- 时隙 8 固定选通 Q1，用于模式灯和 DC 充电灯。
- 时隙 9 根据当前单位选择低边；前三个单位使用 Q1，最后一个单位使用 Q4。

因此完整周期为 10 ms，单个 LED 的理论刷新频率约为 100 Hz。应用只修改 `s_frame` 对应的缓存，不直接操作 GPIO；下一次对应行被扫描时，修改后的内容才会输出。

### 5.3 显示缓存接口

```c
led_clear();
led_all_on();
led_all_off();
led_set_frame(frame);
led_set_row(row, data);
led_set_pixel(row, col, on);
```

- `led_set_row()` 只更新一行，压力显示和电池图标使用此接口，互不覆盖其他行。
- `row` 范围为 0~7，对应 Q1~Q8。
- `col` 范围为 0~7，对应低边线。
- `data` 的 bit 为 1 表示该交点点亮。
- 修改缓存不会改变扫描节拍；显示输出始终由 `led_scan()` 统一完成。
- 多个显示模块更新不同的行时不会互相覆盖；如果两个模块更新同一行，后一次写入会覆盖前一次内容。

### 5.4 总显示开关

```c
led_set_enabled(0U);  /* 关闭所有 LED 输出 */
led_set_enabled(1U);  /* 恢复扫描 */
led_is_enabled();     /* 查询显示是否打开 */
```

关闭显示只关闭高低边输出，不清除显示缓存。因此恢复后会继续显示关闭前的模式、单位、压力值和电池状态。

### 5.5 与按键复用的影响

前 6 条低边同时连接 S1~S6 按键。按键采样期间，`key_scan()` 会暂时把这些 GPIO 从 LED 推挽输出切换成上拉输入；采样结束后再切回 LED 输出。这个切换只发生在每 10 ms 的按键采样时刻，且不会修改 GPIO 输出寄存器中的原值，所以不会破坏显示缓存。应用不应在按键驱动之外再次初始化这些复用引脚。

## 6. 按键扫描和事件

### 6.1 扫描参数

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| `KEY_SCAN_PERIOD_MS` | 10 ms | 实际采样周期 |
| `KEY_DEBOUNCE_MS` | 30 ms | 输入稳定达到该时间才确认状态变化 |
| `KEY_LONG_PRESS_MS` | 800 ms | S1 长按事件门限 |
| `KEY_S3_LONG_PRESS_MS` | 3000 ms | S3 Option Byte 恢复门限 |
| `KEY_LONG_HOLD_MS` | 200 ms | S1 长按后的重复保持事件周期 |

按键为低电平有效：按下时读到 `GPIO_PIN_RESET`，释放时读到 `GPIO_PIN_SET`。

### 6.2 一次按键采样的过程

```text
主循环调用 key_scan()
        |
        v
距离上次采样不足 10 ms？--是--> 立即返回
        |
        否
        v
6 条复用线切换为上拉输入
        |
        v
读取每个按键的当前电平
        |
        v
消抖、累计按下时间、生成事件
        |
        v
6 条复用线恢复为 LED 推挽输出
```

按键与 LED 共用低边线，所以驱动不能在 LED 输出模式下直接读取按键，否则会把矩阵电平误认为按键状态。输入采样结束后必须恢复输出模式，LED 扫描才可以继续正常选通。

### 6.3 消抖和长按计算

实际采样周期为 10 ms，消抖门限为 30 ms，也就是同一电平连续稳定 3 次才确认状态变化：

```text
第一次读到变化：debounce_ticks = 1
第二次读到相同变化：debounce_ticks = 2
第三次读到相同变化：确认 pressed 状态并产生 PRESS 或释放事件
```

确认按下后，`hold_ticks` 每次采样增加 1，因此长按时间按以下公式计算：

```text
持续时间约等于 hold_ticks * 10 ms
```

当前门限为：

- S1：约 800 ms 产生 `KEY_EVENT_LONG_PRESS`，随后每 200 ms 产生一次 `KEY_EVENT_LONG_HOLD`。
- S3：约 3 s 产生一次 `KEY_EVENT_LONG_PRESS`，用于恢复烧录相关 Option Byte。
- S2、S4、S5、S6：目前只产生短按释放事件，不产生长按事件。

长按事件在一次按键保持期间只上报一次；释放后才允许下一次长按重新计时。机械抖动不会直接产生业务事件，只有通过 30 ms 消抖确认后的状态变化才会进入事件缓存。

### 6.4 事件类型

```c
KEY_EVENT_PRESS
KEY_EVENT_SHORT_RELEASE
KEY_EVENT_LONG_PRESS
KEY_EVENT_LONG_HOLD
KEY_EVENT_LONG_RELEASE
```

```c
uint32_t event = key_get_event(KEY_S5);
```

`key_get_event()` 读取后清除事件；`key_peek_event()` 只读取、不清除，适合多个应用模块协同判断。`key_is_pressed()` 查询稳定按下状态，不清除事件。

事件缓存和当前电平是两种不同的数据：

- `key_is_pressed()` 适合判断“按键现在是否仍按住”。
- `key_get_event()` 适合执行一次性动作，例如切换模式、加 1 或减 1。
- `key_peek_event()` 适合一个事件需要被多个模块观察的情况，但不会消费事件。

推荐在主循环中只保留一处统一分发按键事件：

```c
key_scan();
display_control_scan();
```

具体显示业务通过 `display_control_scan()` 消费事件；其他模块如需扩展功能，应使用 `key_get_event()` 或应用层标志接口，避免多个模块重复清除同一个事件。

## 7. 按键功能

| 按键 | 短按 | 长按/其他 |
| --- | --- | --- |
| S1 | 启动/暂停压力泵循环：发送 CMD=0x03 或 CMD=0x04 | 长按约 800 ms 在“显示开启/关闭”之间切换 |
| S2 | 目标压力值减 1，000 时保持 | 当前未绑定其他动作 |
| S3 | 向 U2 发送 CMD=0x01，切换 U2 的 PB3 灯并等待返回 | 长按约 3 秒恢复 PB6=SWD、PC0=GPIO 的烧录安全配置 |
| S4 | 目标压力值加 1，999 时保持 | 当前未绑定其他动作 |
| S5 | 切换工作模式 | 当前未绑定长按动作 |
| S6 | 切换压力单位 | 当前未绑定长按动作 |

S1 短按先主动查询一次 U2 当前压力泵状态，再根据返回值在启动和暂停之间切换：泵停止时发送当前目标压力（Pa）和当前模式的 `CMD=0x03`，泵运行时发送无载荷的 `CMD=0x04`。查询超时或返回无效时不执行切换。上电目标压力默认为 `000`，目标压力为 `0 Pa` 或大于 `99900000 Pa` 时不发送启动命令，必须先用 S2/S4 设置有效的非零目标压力。该上限对应 `999.00 BAR`，与当前显示目标范围统一。S1 长按关闭 U1 显示时，显示缓存仍在更新，但 LED 输出被 `led_set_enabled(0U)` 强制关闭；再次长按 S1 会恢复原显示内容。S3 不操作 U1 本地显示，只通过串口切换 U2 的 PB3 灯，并等待 U2 返回实际状态。

## 8. 应用层按键标志

`display_control_driver.h` 定义了应用层标志：

```c
DISPLAY_KEY_FLAG_S1
DISPLAY_KEY_FLAG_S2
DISPLAY_KEY_FLAG_S3
DISPLAY_KEY_FLAG_S4
DISPLAY_KEY_FLAG_S5
DISPLAY_KEY_FLAG_S6
```

读取接口：

```c
uint32_t flags = display_control_get_key_flags();
if ((flags & DISPLAY_KEY_FLAG_S5) != 0U)
{
    /* S5 在最近一次扫描期间产生过可处理事件 */
}
```

该接口采用“读取后清除”。标志表示按键事件，不表示按键当前是否持续按下。当前置位规则为：S2/S4/S5/S6 短按释放置位，S1 长按置位，S3 短按释放或长按事件置位。

如果只需要判断当前电平，使用 `key_is_pressed()`；如果需要区分短按、长按，使用 `key_get_event()` 或在事件分发层增加专用处理。

## 9. 工作模式灯

模式状态由 `mode_led_driver.c` 保存，默认是皮筏艇。S5 每次短按切换一次，最后一个模式后回到第一个。

| 枚举 | 含义 | 灯位 |
| --- | --- | --- |
| `MODE_LED_RAFT` | 皮筏艇 | L00-L01 |
| `MODE_LED_AIR_BED` | 充气床 | L02-L01 |
| `MODE_LED_TIRE` | 轮胎 | L03-L01 |

调用接口：

```c
mode_led_init();
mode_led_next();
ModeLedMode_t mode = mode_led_get_current();
uint8_t mask = mode_led_get_mask();
```

模式灯在 LED 扫描的 Q1 辅助时隙点亮，三个模式灯最多同时点亮一个。

## 10. 压力单位灯

单位状态由 `unit_led_driver.c` 保存，默认是 BAR。S6 每次短按切换一次，最后一个单位后回到第一个。

| 枚举 | 含义 | 灯位 |
| --- | --- | --- |
| `UNIT_LED_BAR` | BAR | L12-L01 |
| `UNIT_LED_PSI` | PSI | L13-L01 |
| `UNIT_LED_KPA` | KPA | L14-L01 |
| `UNIT_LED_KG_CM2` | kg/cm2 | L14-L08 |

调用接口：

```c
unit_led_init();
unit_led_next();
UnitLedUnit_t unit = unit_led_get_current();
uint8_t index = unit_led_get_index();
```

前三个单位使用 Q1 公共端，最后一个单位使用 Q4/P08 公共端。压力显示的小数点由各排数字的段码独立控制，按照当前数值大小自适应显示两位、一位或不显示小数；单位指示灯在独立辅助时隙扫描，不会覆盖压力数字缓存。

## 11. 压力数码管显示

### 11.1 上下排分配

| 显示内容 | 公共端 | 缓存行索引 |
| --- | --- | --- |
| 上排实际值 | Q2~Q4 | 1~3 |
| 下排目标值 | Q5~Q7 | 4~6 |

实际值和目标值的设置参数统一采用“数值放大 100 倍”的 `uint32_t` 整数格式，允许输入范围为 `0~99900`，对应物理范围 `0.00~999.00`。例如在 BAR 单位下传入 `259` 表示 `2.59 BAR`，传入 `2590` 表示 `25.90 BAR`，传入 `99900` 表示 `999.00 BAR`。驱动内部统一保存 `0.01 BAR` 的物理值，单位切换时实际值和目标值都从该基础值重新换算，不进行多次累积换算。显示格式固定如下：

| 单位 | 显示格式 | 小数点位置 | 示例 |
| --- | --- | --- | --- |
| BAR | `X.XX`、`XX.X` 或 `XXX` | `0.00~9.99` 百位后，`10.0~99.9` 十位后，`100~999` 不显示 | `259` 显示为 `2.59`，`2590` 显示为 `25.9` |
| PSI | `X.XX`、`XX.X` 或 `XXX` | 按换算后的数值大小自适应 | `255` 表示 `2.55 PSI` |
| KPA | `X.XX`、`XX.X` 或 `XXX` | 按换算后的数值大小自适应 | `25000` 表示 `250.00 KPA` |
| kg/cm2 | `X.XX`、`XX.X` 或 `XXX` | 按换算后的数值大小自适应 | `255` 显示为 `2.55`，`2640` 显示为 `26.4`，`99900` 显示为 `999` |

单位换算采用以下关系，并进行四舍五入：

```text
PSI      = BAR × 14.5038
KPA      = BAR × 100
kgf/cm2  = BAR × 1.019716
```

换算后所有单位都按同一套自适应格式覆盖 `0.00~999`：`0.00~9.99` 使用两位小数，`10.0~99.9` 使用一位小数，`100~999` 使用整数；只有超过 `999` 才按最大值 `999` 显示。这样 `25.9 BAR`（内部输入 `2590`）会显示约 `26.4 kgf/cm2`，不会错误地显示 `9.99`。内部物理值保留，切换到其他单位时继续按真实值换算。S4/S2 每次按当前显示精度的最小步进增加或减少，当前显示为 `999` 时继续加一保持 `999`，当前显示为 `000` 时继续减一保持 `000`。

### 11.2 段线映射

| 段 | 低边 |
| --- | --- |
| A | L00 |
| B | L02 |
| C | L03 |
| D | L04 |
| E | L05 |
| F | L12 |
| G | L13 |
| DP | L14 |

### 11.3 调用接口

```c
pressure_display_init();
/* 输入值按当前单位解释；上电默认单位为 BAR。 */
pressure_display_set_actual(123U);
pressure_display_set_target(456U);
pressure_display_target_increase();
pressure_display_target_decrease();

uint16_t actual = pressure_display_get_actual();
uint16_t target = pressure_display_get_target();
```

上电时实际值和目标值均为 `000`，单位默认为 BAR。调用 `set_actual()` 或 `set_target()` 会按当前单位转换到内部 `0.01 BAR` 后，立即重算两排段码。S6 切换单位后，`display_control_scan()` 会调用 `pressure_display_on_unit_changed()`，同时刷新实际值、目标值和小数点位置。

## 12. 电池图标

电池图标使用 Q8/P15（PC0）公共端，即缓存行 7。

### 12.1 图标组成

| 内容 | 矩阵位 | 说明 |
| --- | --- | --- |
| 外框 | bit0~bit3 | L00、L02、L03、L04，始终保持长亮 |
| 第一格 | bit6 | L13-L15 |
| 第二格 | bit5 | L12-L15 |
| 第三格 | bit4 | L05-L15 |

协议返回的 `BatLevel` 范围为 0~3，其中 0 表示满电、3 表示低电；显示层将其转换为
`display_level = 3 - BatLevel` 后，以 3/2/1/0 格显示。超出范围的协议帧会被判定为无效。

### 12.2 充电动画

```c
battery_icon_set_level(2U);
battery_icon_set_charging(1U);
```

未充电时静态显示当前电量。充电时每约 500 ms 在对应的两个显示状态之间切换：
3/2 格电量在 3 格和 2 格之间闪烁，1 格电量在 2 格和 1 格之间闪烁，0 格电量在 1 格和空电外框之间闪烁。

```c
battery_icon_get_level();
battery_icon_get_displayed_level();
battery_icon_is_charging();
```

前者返回实际电量，后者可返回动画当前显示格数。

- `L05-L01`

dc_led_set_charging(1U);  /* 充电，点亮两只灯 */

## 14. Option Byte 和烧录复用

### 14.1 上电检查

`option_bytes_boot_check()` 在按键、LED 初始化前执行：

1. 临时把 S1/P00/PA0 配置为上拉输入。
2. 如果检测到 S1 按下，保留当前 Option Byte，方便烧录器连接和恢复。
3. 如果 S1 未按下，则检查当前复用模式。
4. 当前模式不符合显示运行模式时才写入 Option Byte；模式已经正确时不重复写入。

正常显示运行模式调用的是 `OB_SWD_PC0_GPIO_PB6`，含义是 PC0 作为 SWD、PB6 作为 GPIO。这样 Q1/P01/PB6 可以被 LED 矩阵使用。

### 14.2 S3 长按恢复

运行期间 `option_bytes_scan()` 检查 S3 长按事件。S3 持续按下约 3 秒后调用 `OB_SWD_PB6_GPIO_PC0`，含义是 PB6 作为 SWD、PC0 作为 GPIO。Option Byte 重载会触发系统复位，函数正常情况下不会返回。

恢复后烧录器可以使用 PB6/SWD 连接；重新进入显示运行模式时，上电不按 S1，系统会再次检查并切换到正常显示配置。

## 15. PB4 单线半双工串口

### 15.1 硬件配置

工程新增 `uart_halfduplex_driver.c/.h`，使用 `USART1` 的单线半双工模式：

| 项目 | 配置 |
| --- | --- |
| 收发引脚 | PB4 |
| GPIO 复用 | AF1 / USART1 |
| 波特率 | 115200 baud |
| 数据格式 | 8 数据位、无校验、1 停止位（8N1） |
| 通信方向 | 主控主动发起，发送和接收分时进行 |

半双工模式由 HAL 的 `HAL_HalfDuplex_Init()` 配置，使 USART1 在 PB4 上分时收发。发送前调用 `HAL_HalfDuplex_EnableTransmitter()`，发送结束后调用 `HAL_HalfDuplex_EnableReceiver()`。外部设备必须支持单线半双工，且总线上不能同时有两个发送端。

### 15.2 调用接口

```c
uint8_t request[] = { 0x01U, 0x02U };
uint8_t response[8];
int32_t result;

result = uart_halfduplex_send(request, sizeof(request),
                              UART_HALF_DUPLEX_TIMEOUT_MS);
if (result >= 0)
{
    result = uart_halfduplex_receive(response, sizeof(response),
                                     UART_HALF_DUPLEX_TIMEOUT_MS);
}
```

常用接口如下：

```c
uart_halfduplex_init();
uart_halfduplex_set_tx();
uart_halfduplex_set_rx();
uart_halfduplex_send(data, length, timeout_ms);
uart_halfduplex_receive(data, max_length, timeout_ms);
```

`uart_halfduplex_send()` 内部调用 `HAL_UART_Transmit()`，HAL 会等待最后一个停止位发送完成，然后驱动自动切回接收方向。USART1 中断进入 `HAL_UART_IRQHandler()`；每完成 1 字节接收，`HAL_UART_RxCpltCallback()` 将该字节写入 64 字节环形缓冲区，并立即重新启动下一字节的 `HAL_UART_Receive_IT()`。`uart_halfduplex_receive()` 只从环形缓冲区取数据并支持超时等待。发送或接收超时、参数错误、未初始化时返回 `-1`。驱动不会自动发送数据，只有业务代码调用发送接口时才会发起通信。

### 15.3 工作流程

系统启动时由 `main()` 调用一次 `uart_halfduplex_init()`。初始化完成后，USART1 默认处于接收方向，并通过 `HAL_UART_Receive_IT()`等待第一个字节。中断向量 `USART1_IRQHandler()` 位于 `Src/py32f002b_it.c`，它经由 `uart_halfduplex_irq_handler()`调用 `HAL_UART_IRQHandler()`；中断中不解析协议，也不执行耗时业务。

每次通信建议按照“主控发送一帧、等待从设备响应”的顺序执行：

1. 准备待发送的协议帧。
2. 调用 `uart_halfduplex_send()`。驱动会清除上一事务残留数据，切换 PB4 到发送方向，等待 TXE 和 TC，并在最后一个停止位发送完成后自动切回接收方向。
3. 调用 `uart_halfduplex_receive()` 读取响应。接收字节已经由 RXNE 中断放入环形缓冲区，主循环接口只负责取出数据并进行协议校验。
4. 根据返回值判断结果：大于等于 0 表示实际收发字节数，`-1` 表示参数错误、未初始化或在超时时间内没有收到数据。

示例：

```c
#include "uart_halfduplex_driver.h"

static void app_uart_query(void)
{
    uint8_t request[] = {0x01U, 0x03U};
    uint8_t response[8];
    int32_t received;

    if (uart_halfduplex_send(request, sizeof(request), 100U) < 0)
    {
        return;
    }

    received = uart_halfduplex_receive(response, sizeof(response), 100U);
    if (received > 0)
    {
        /* 在主循环中校验 response[0..received-1]，不要在 ISR 中解析。 */
    }
}
```

### 15.4 使用注意事项

- PB4 是单根信号线，外部设备和主控必须共地；建议总线保持空闲高电平，并根据硬件距离配置上拉。
- 半双工总线同一时刻只能有一个发送端。当前约定由主控主动发起，从设备只在收到请求后返回。
- 环形缓冲区容量为 64 字节。主循环应及时调用 `uart_halfduplex_receive()`，否则缓冲区满后新到字节会被丢弃。
- `timeout_ms` 是本次等待的最长时间，单位为毫秒；超时不会关闭串口，下一次事务仍可继续使用。
- 发送期间接收中断会暂时关闭，防止把主控自己的发送数据当成响应；发送结束后会重新打开接收中断。

## 16. AA55 控制协议框架

串口底层之上增加了 `uart_protocol_driver.c/.h`，用于统一处理控制命令的组帧、接收状态机和校验。当前协议帧格式如下：

```text
AA 55 LEN CMD PAYLOAD[LEN] CHK
```

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 2 字节 | 固定为 `0xAA 0x55` |
| `LEN` | 1 字节 | 有效载荷长度，不包含 `CMD` 和 `CHK` |
| `CMD` | 1 字节 | 命令码，由业务层定义 |
| `PAYLOAD` | `LEN` 字节 | 命令参数，可为空 |
| `CHK` | 1 字节 | `LEN + CMD + PAYLOAD` 的 8 位累加和 |

协议层最大载荷为 48 字节。接收解析使用中断状态机，能够在无效数据、帧头错位、长度非法、校验失败或半帧超时后自动重新搜索 `AA 55`；主循环通过 `uart_control_task()` 读取完整数据包。通信事务锁保证等待返回期间不能再次发送。

### 16.1 初始化和主循环

`main()` 已按以下顺序初始化和运行协议层：

```c
uart_control_init();

while (1)
{
    /* 其他按键和显示扫描 */
    uart_control_task();
    uart_command_scan();
}
```

### 16.2 发送命令

业务代码不需要自己拼接帧头、长度或校验，只传入命令码和载荷：

```c
uint8_t payload[] = {0x01U, 0x02U};

if (uart_protocol_send(0x10U, payload, sizeof(payload)) < 0)
{
    /* 底层未初始化、参数超限或发送超时 */
}
```

无参数命令可以传入 `0` 和空指针：

```c
uart_protocol_send(0x20U, 0, 0U);
```

当前已实现 `CMD=0x01` LED 开关、`CMD=0x02` 周期状态查询、`CMD=0x03` 压力泵启动和 `CMD=0x04` 压力泵暂停。`CMD=0x02` 返回充电状态、电量、Pa 气压和 1 字节压力泵状态；`CMD=0x03` 携带 4 字节 Pa 目标压力和 1 字节模式，`CMD=0x04` 无请求载荷；后两者均返回 1 字节压力泵状态。后续命令的返回也使用请求中的相同 `CMD`，返回载荷长度和内容由对应命令单独定义。

### 16.3 获取接收命令

协议状态机在 USART 接收中断中推进，主循环通过 `uart_control_task()` 读取已经校验成功的完整帧：

```c
uint8_t cmd;
uint8_t length;
uint8_t payload[UART_PROTOCOL_MAX_PAYLOAD];

if (uart_protocol_frame_available() != 0U)
{
    if (uart_protocol_get_frame(&cmd, payload, &length) != 0U)
    {
        /* 根据 cmd 分发业务，payload[0..length-1] 是命令参数。 */
    }
}
```

协议层暂存一帧待处理数据；业务处理完成后应及时调用 `uart_protocol_get_frame()`。如果上一帧尚未取走又收到新帧，新帧会被丢弃，不会覆盖正在等待业务处理的帧。

### 16.4 后续增加命令

后续扩展只需要在应用层增加命令分发，不需要修改帧格式和串口中断。例如可以按以下方式集中管理：

```c
switch (cmd)
{
    case 0x10U:
        /* 设置压力或目标值 */
        break;
    case 0x20U:
        /* 查询当前状态 */
        break;
    default:
        /* 未知命令 */
        break;
}
```

多字节数值建议统一使用小端格式；响应帧可以复用相同的 `CMD`，并将 `PAYLOAD[0]` 作为状态码，例如 `0x00` 表示成功、`0x01` 表示未知命令、`0x02` 表示参数错误。

## 17. 推荐的业务调用方式

新增业务应通过应用接口修改状态，不要直接写矩阵 GPIO。例如：

```c
/* 设置当前压力和电池状态；显示层先将 BatLevel 转换为 display_level。 */
pressure_display_set_actual(actual_pressure);
battery_icon_set_level(display_level);
battery_icon_set_charging(is_charging);
dc_led_set_charging(is_charging);

/* 查询当前模式和单位 */
ModeLedMode_t mode = mode_led_get_current();
UnitLedUnit_t unit = unit_led_get_current();

/* 读取应用层按键标志 */
uint32_t key_flags = display_control_get_key_flags();
```

应用层只需保证 `key_scan()`、`led_scan()` 和 `display_control_scan()` 持续运行；不要在其他模块中再建立一套 LED 扫描定时器。

## 18. 当前状态和扩展注意事项

- 模式、单位、压力值、电池状态、DC 状态和显示开关目前都保存在 RAM 中，断电后恢复为初始化默认值。
- 模式默认值为皮筏艇，单位默认值为 BAR，压力实际值和目标值默认均为 000，DC 默认关闭，电池默认 0 格且未充电。
- 按键和 LED 低边复用，按键采样期间会暂时停止这些低边的 LED 驱动，这是硬件复用方案决定的。
- PC0/RST、PB6/SWD、PA2/SWC 等调试/复位相关引脚的复用由 Option Byte 决定，修改前必须保留烧录恢复路径。
- `Drivers/` 下的 PY32 官方驱动不应为了实现业务功能而修改；业务逻辑放在 `Src/` 和 `Inc/` 的应用驱动中。
