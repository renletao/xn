# PY32F002B 控制协议通信规则

## 1. 适用范围

本文档说明当前 U1 控制板串口协议的通信规则，以及已经实现的 LED、充电状态和压力泵控制命令。

当前工程已实现 AA55 帧接收、长度检查、校验和验证、协议状态机、`CMD=0x01` LED 控制、`CMD=0x02` 充电状态查询、`CMD=0x03` 压力泵启动和 `CMD=0x04` 压力泵暂停。

## 2. 串口参数

| 项目 | 配置 |
| --- | --- |
| 芯片 | PY32F002B |
| 通信引脚 | PB4 |
| 外设 | USART1 单线半双工 |
| GPIO 复用 | AF1 / USART1 |
| 波特率 | 115200 bit/s |
| 数据格式 | 8 数据位、无校验、1 停止位（8N1） |
| 通信角色 | U1 控制板为主控，主动发起通信 |
| 总线空闲电平 | 高电平 |

PB4 在同一根线上分时完成发送和接收。主控发送完成后切换为接收方向，外部设备只能在收到主控请求后应答。总线同一时刻只能有一个发送端，设备不得主动抢占发送。

## 3. 数据帧格式

### 3.1 帧结构

```text
AA 55 LEN CMD PAYLOAD[LEN] CHK
```

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| `AA` | 1 字节 | 固定帧头，值为 `0xAA` |
| `55` | 1 字节 | 固定帧头，值为 `0x55` |
| `LEN` | 1 字节 | `PAYLOAD` 的字节数，范围 `0..48` |
| `CMD` | 1 字节 | 命令码，具体含义由业务定义 |
| `PAYLOAD` | `LEN` 字节 | 命令参数或返回数据，可以为空 |
| `CHK` | 1 字节 | 长度、命令和载荷的 8 位累加校验值 |

完整帧长度为：

```text
完整帧长度 = LEN + 5
```

`LEN` 只表示 `PAYLOAD` 长度，不包含帧头、`CMD` 和 `CHK`。

### 3.2 校验算法

```text
CHK = (LEN + CMD + PAYLOAD[0] + PAYLOAD[1] + ... + PAYLOAD[LEN-1]) & 0xFF
```

校验规则：

- `AA` 和 `55` 不参与校验。
- 从 `LEN` 开始累加，包括 `CMD` 和所有载荷字节。
- 只保留累加结果的低 8 位，高位溢出丢弃。
- 无载荷时，`CHK = LEN + CMD` 的低 8 位。

对应的 C 语言写法：

```c
uint8_t checksum = length + cmd;
for (i = 0U; i < length; ++i)
{
    checksum = (uint8_t)(checksum + payload[i]);
}
```

### 3.3 帧示例

无载荷，`CMD=0x01`：

```text
AA 55 00 01 01
```

校验：`0x00 + 0x01 = 0x01`。

载荷为 `0x02`，`CMD=0x20`：

```text
AA 55 01 20 02 23
```

校验：`0x01 + 0x20 + 0x02 = 0x23`。

载荷为小端 16 位数值 `0x007B`，`CMD=0x11`：

```text
AA 55 02 11 7B 00 8E
```

校验：`0x02 + 0x11 + 0x7B + 0x00 = 0x8E`。

## 4. CMD=0x01 LED 开关

该命令由 U1 主控发送给 U2，用于控制 U2 的 PB3 灯。U1 发送请求后必须等待 U2 返回状态帧；请求和返回使用相同的 `CMD=0x01`，返回载荷携带 U2 执行后的实际 LED 状态。S3 短按切换记录的 U2 状态并发起一次完整的发送/等待返回流程，U1 本地 LED 不受该命令影响。

| 项目 | 规定 |
| --- | --- |
| 命令码 | `0x01` |
| `LEN` | 必须为 `1` |
| `PAYLOAD[0] = 0x00` | 关闭 LED 显示 |
| `PAYLOAD[0] = 0x01` | 开启 LED 显示 |
| 其他载荷值 | 忽略，不改变当前状态 |
| 其他载荷长度 | 忽略，不改变当前状态，也不返回应答 |

返回帧规则：

| 字段 | 规定 |
| --- | --- |
| `CMD` | 仍为 `0x01` |
| `LEN` | 固定为 `1` |
| `PAYLOAD[0]` | U2 执行后的实际状态，`0x00` 关闭，`0x01` 开启 |

### 4.1 关闭 LED

```text
AA 55 01 01 00 02
```

校验：`0x01 + 0x01 + 0x00 = 0x02`。

收到并通过校验后，U2 关闭 PB3 灯。U1 只有收到返回帧后才记录该状态，U1 本地 LED 显示不受影响。

返回帧：

```text
AA 55 01 01 00 02
```

### 4.2 开启 LED

```text
AA 55 01 01 01 03
```

校验：`0x01 + 0x01 + 0x01 = 0x03`。

收到并通过校验后，U2 开启 PB3 灯。U1 只有收到返回帧后才记录该状态，S3 短按则根据记录状态切换下一次请求。

返回帧：

```text
AA 55 01 01 01 03
```

## 5. CMD=0x02 充电状态、电量和气压查询

U1 作为主控每 1 秒发起一次查询。该查询不带请求载荷，U2 收到后返回当前充电状态、电量百分比、Pa 单位的气压值和压力泵状态。S3 的 LED 控制事务正在发送或等待返回时，本次查询延后到下一轮。

### 5.1 查询请求

请求帧固定为：

```text
AA 55 00 02 02
```

其中 `LEN=0`，`CMD=0x02`，校验值为 `0x00 + 0x02 = 0x02`。

### 5.2 返回载荷

返回帧的 `CMD` 仍为 `0x02`，`LEN` 固定为 `7`，载荷字段如下：

| 字段 | 偏移 | 长度 | 说明 |
| --- | ---: | ---: | --- |
| `STATUS` | 0 | 1 | `0x00` 未充电，`0x01` 正在充电 |
| `BATTERY` | 1 | 1 | 电量百分比，范围 `0~100` |
| `PRESSURE` | 2 | 4 | `uint32_t`，Pa 单位，小端序，无符号整数 |
| `PUMP` | 6 | 1 | 压力泵状态：`0x00` 停止/暂停，`0x01` 运行 |

收到未定义的充电状态或大于 `100` 的电量值时，U1 判定返回无效，不更新显示。

例如，U2 返回“正在充电、电量 75%、气压 101325 Pa、压力泵运行”：

```text
AA 55 07 02 01 4B CD 8B 01 00 01 AF
```

其中 `101325 = 0x00018BCD`，按小端序发送为 `CD 8B 01 00`。校验为：

```text
0x07 + 0x02 + 0x01 + 0x4B + 0xCD + 0x8B + 0x01 + 0x00 + 0x01 = 0x01AF
取低 8 位得到 0xAF
```

### 5.3 U1 显示规则

- `STATUS=0x01` 时点亮 DC 指示灯并启动电池充电动画；`STATUS=0x00` 时关闭 DC 指示灯并停止动画。
- 电量格严格按“大于”判断：`<=30%` 为 0 格，`>30%` 为 1 格，`>60%` 为 2 格，`>80%` 为 3 格。
- `PRESSURE` 先从 Pa 转换为当前选择的压力单位，再更新数码管上半部分的实际压力显示。下半部分目标压力保持不变；`PUMP` 同步到 U1 本地记录的压力泵状态（`uart_command_is_pump_running()`），S1 短按前还会再主动查询一次，以消除最长 1 秒的缓存偏差。
- 查询超时、发送失败或返回无效时，保留最近一次有效显示值，下一轮继续查询。

### 5.4 软件处理位置

`uart_command_driver.c` 的 `uart_command_scan()` 使用 `HAL_GetTick()` 维护 1 秒查询周期；它只提交请求，不阻塞等待。统一的 `uart_control_task()` 负责非阻塞接收返回、校验命令和 100 ms 超时。显示层通过 `uart_command_take_charging_status()` 消费最近一次有效数据。

## 6. CMD=0x03/0x04 压力泵控制

`CMD=0x03` 用于设置目标压力和充气模式并启动压力泵，`CMD=0x04` 用于暂停压力泵。目标压力统一使用 Pa；模式值与 U1 当前模式灯枚举一致。

### 6.1 CMD=0x03 启动压力泵

请求载荷固定为 5 字节：

| 字段 | 偏移 | 长度 | 说明 |
| --- | ---: | ---: | --- |
| `TARGET_PRESSURE` | 0 | 4 | `uint32_t`，Pa，小端序；范围 `1~99900000` |
| `MODE` | 4 | 1 | `0x00` 皮筏艇，`0x01` 充气床，`0x02` 车胎 |

请求帧格式：

```text
AA 55 05 03 TARGET_PRESSURE[4] MODE CHK
```

例如目标压力为 `25300 Pa`、模式为皮筏艇：

```text
25300 = 0x000062D4
小端序：D4 62 00 00

AA 55 05 03 D4 62 00 00 00 3E
```

校验为：`0x05 + 0x03 + 0xD4 + 0x62 + 0x00 + 0x00 + 0x00 = 0x013E`，取低 8 位得到 `0x3E`。

U2 返回 `CMD=0x03`、`LEN=1` 的状态帧：

| `PAYLOAD[0]` | 含义 |
|---:|---|
| `0x00` | 已停止/暂停 |
| `0x01` | 已启动，正在充气 |
| `0x02` | 参数无效或启动失败 |

启动成功返回示例：

```text
AA 55 01 03 01 05
```

### 6.2 CMD=0x04 暂停压力泵

暂停请求不带载荷：

```text
AA 55 00 04 04
```

U2 收到后立即停止压力泵，保留目标压力和模式，并返回 `CMD=0x04`、`LEN=1` 的状态帧：

| `PAYLOAD[0]` | 含义 |
|---:|---|
| `0x00` | 已暂停/已停止 |
| `0x01` | 仍在运行，暂停失败 |
| `0x02` | 控制异常 |

正常暂停返回：

```text
AA 55 01 04 00 05
```

如果压力泵本来已经停止，U2 仍返回 `0x00`，暂停命令保持幂等。

### 6.3 S1 短按启动/暂停循环

U1 的 S1 短按释放先主动查询一次 U2 的当前压力泵状态，收到合法的 `CMD=0x02` 返回后再执行压力泵切换。主动读取是为了消除本地缓存的滞后：U2 在压力达到目标后会自动停机，只依赖 1 秒周期查询时，U1 可能仍认为泵在运行而错发 `CMD=0x04`。

1. 查询返回状态为停止时，发送 `CMD=0x03`；目标压力取当前下排设定值转换后的 Pa，模式取当前模式灯状态。
2. 查询返回状态为运行时，发送 `CMD=0x04`。
3. 查询返回无效或超时不执行切换；若 1 秒周期轮询恰好正在进行同一次 `CMD=0x02` 查询，则直接复用该次返回，不再重复发送。只有收到 `CMD=0x03`/`CMD=0x04` 的成功返回后，U1 才更新本地泵状态。
4. S1 长按功能保持不变，仍用于切换 U1 本地显示开关。

上电目标压力默认为 `000`。为防止无目标压力时误启动，目标压力为 `0 Pa` 或大于 `99900000 Pa` 时，U1 不提交 `CMD=0x03`；启动前必须先用 S2/S4 将目标压力设置为有效的非零值。该上限对应当前显示目标的最大值 `999.00 BAR`，保证显示范围内的目标值都能编码到 `CMD=0x03`。

因此短按序列为：

```text
启动 -> 暂停 -> 启动 -> 暂停 -> ...
```

`CMD=0x03`、`CMD=0x04` 与 `CMD=0x01`、`CMD=0x02` 共用串口事务锁；已有事务完成前不会并发发送新帧。

## 7. 软件处理位置

`uart_protocol_driver.c` 在 USART 接收中断中完成帧解析和校验；`uart_command_driver.c` 内的统一控制入口负责事务锁、非阻塞等待返回和超时。主循环只需调用：

```c
uart_control_task();
uart_command_scan();
```

业务命令处理在主循环中执行，不在 USART 接收中断中执行。每次请求获取事务锁，发送后进入非阻塞等待；100 ms 内收到与当前请求相同 `CMD` 的有效返回帧才算通信成功，等待期间再次发送返回 BUSY。命令处理接口位于：

```text
Inc/uart_command_driver.h
Src/uart_command_driver.c
```

## 8. 数据编码规则

### 8.1 字节序

- 8 位数据占 1 字节，直接传输。
- 16 位数据默认使用小端序，低字节在前。
- 32 位数据默认使用小端序，低字节在前。
- 例如十进制 `1000` 的 16 位编码为 `E8 03`。

### 8.2 数值和小数

载荷中的数值必须在对应命令中明确单位和有效范围。带小数的数值建议使用定点整数传输，不直接传输 C 语言 `float`。

例如单位为 `0.1 bar` 时，整数 `253` 表示 `25.3 bar`。

### 8.3 枚举

枚举值从 `0` 开始分配。接收方收到未定义的枚举值时，应按参数无效处理，不能自动转换为其他值。

### 8.4 未使用字段

已经定义的保留字节发送时填 `0x00`。接收方对明确标记为保留的字段不做业务处理。

## 9. 通信流程

### 9.1 主控发送请求

```text
主控                         外部设备
  | ---- 完整请求帧 --------> |
  |                          | 接收并校验
  | <---- 应答帧 ------------ |
```

通信顺序如下：

1. 主控组装请求帧并发送。
2. 外部设备接收完整帧，检查帧头、长度和校验值。
3. 校验正确后，外部设备根据 `CMD` 处理载荷。
4. 外部设备处理完成后返回应答帧。
5. 主控等待应答或等待超时。

主控发送期间，外部设备不能同时发送。主控发送完最后一个停止位后，才进入接收状态。每一次通信事务都必须收到匹配返回帧才算完成；发送后 100 ms 内没有收到有效返回帧，则本次通信超时失败。

### 9.2 返回帧规则

命令执行成功后，返回帧使用与请求帧相同的 `CMD`。返回帧的 `LEN` 和 `PAYLOAD` 由对应命令定义，可以只返回一个状态字节，也可以返回多个数据字段。

因此，设计带数据的命令时必须分别定义请求载荷和返回载荷的长度、字段含义、字节序、单位及有效范围。请求执行失败时，也必须定义是否返回错误状态以及错误状态的编码。

当前各命令的返回载荷如下：

| 命令 | 返回载荷长度 | 返回载荷含义 |
| --- | ---: | --- |
| `CMD=0x01` | 1 | U2 的 PB3 LED 实际状态：`0x00` 关，`0x01` 开 |
| `CMD=0x02` | 7 | 充电状态 1 字节、电量 1 字节、气压 Pa 4 字节小端序、压力泵状态 1 字节 |
| `CMD=0x03` | 1 | 压力泵状态：`0x00` 停止/暂停，`0x01` 运行，`0x02` 参数无效或启动失败 |
| `CMD=0x04` | 1 | 暂停结果：`0x00` 已暂停/停止，`0x01` 仍运行，`0x02` 控制异常 |

所有命令仍必须保持相同 `CMD` 和统一帧格式。`CMD=0x03` 的成功返回只表示 U2 接受并启动了压力泵；实际压力仍由后续 `CMD=0x02` 周期查询获取。

### 9.3 帧接收判断

接收方按以下顺序解析：

1. 搜索连续字节 `0xAA 0x55`。
2. 读取 `LEN`，大于 48 时判定为非法帧。
3. 读取 1 字节 `CMD`。
4. 按 `LEN` 读取载荷。
5. 读取 `CHK` 并重新计算校验值。
6. 校验一致时，帧才交给业务层处理。

帧头错误、长度非法或校验失败的帧直接丢弃，并重新搜索下一组 `AA 55`。

### 9.4 半帧超时

当前协议规定：一帧已经开始接收后，如果连续 100 ms 没有收到下一个字节，则认为当前帧超时。接收方丢弃半帧，并重新搜索 `AA 55`。

## 10. 当前软件接口

协议驱动文件为：

- `Inc/uart_protocol_driver.h`
- `Src/uart_protocol_driver.c`

### 10.1 初始化

底层串口必须先初始化，再初始化协议层：

```c
uart_control_init();
```

### 10.2 主循环解析

主循环中持续调用：

```c
    uart_control_task();
    uart_command_scan();
```

串口接收中断直接推进 AA55 状态机并保存完整数据包；主循环任务只读取完整包、匹配返回并执行超时处理。

### 10.3 获取有效帧

```c
uint8_t cmd;
uint8_t length;
uint8_t payload[UART_PROTOCOL_MAX_PAYLOAD];

if (uart_protocol_frame_available() != 0U)
{
    if (uart_protocol_get_frame(&cmd, payload, &length) != 0U)
    {
        /* cmd 为命令码，payload[0..length-1] 为载荷。 */
    }
}
```

只有帧头、长度和校验全部正确的帧才会通过 `uart_protocol_get_frame()` 返回。

### 10.4 发送帧

业务代码只需要传入命令码和载荷，协议驱动自动生成帧头、长度和校验：

```c
uint8_t payload[] = { 0x02U };

uart_protocol_send(0x20U, payload, sizeof(payload));
```

无载荷时：

```c
uart_protocol_send(0x01U, 0, 0U);
```

返回值大于等于 0 表示实际发送的帧长度，返回 `-1` 表示参数错误、协议层未初始化或底层发送失败。

## 11. 当前限制

- 最大载荷长度为 48 字节。
- 完整帧最大长度为 53 字节。
- 底层接收环形缓冲区为 64 字节。
- 协议层当前只暂存一帧有效数据；上一帧尚未读取时，新帧会被丢弃。
- 当前实现 `CMD=0x01` LED 开关、`CMD=0x02` 周期状态查询、`CMD=0x03` 压力泵启动和 `CMD=0x04` 压力泵暂停，其他 `CMD` 暂不处理。
